## Proof

**Claim.** Yes — Reed-Muller codes can be decoded by comparing the received vect
or to every codeword and selecting the closest one (minimum-distance, i.e. maxim
um-likelihood decoding). This is always possible in principle; the only caveat i
s computational cost, not feasibility.

---

### 1. Reed-Muller codes are finite linear codes

The Reed–Muller code $\mathcal{R}(r,m)$ is a binary linear code of length $n = 2
^m$ and dimension

$$k = \sum_{i=0}^{r} \binom{m}{i}.$$

Being a linear code, it has exactly $|\mathcal{R}(r,m)| = 2^k$ codewords — a **f
inite** number. The code is defined as the image of the evaluation map

$$\mathrm{ev} : \mathbb{F}_2[x_1,\dots,x_m]_{\deg \le r} \longrightarrow \mathbb
{F}_2^{2^m},$$

which sends every multilinear polynomial of degree $\le r$ to its vector of valu
es on all $2^m$ points of $\mathbb{F}_2^m$. Since the domain is a finite-dimensi
onal vector space over $\mathbb{F}_2$, its image is a finite set. Hence the set
of codewords can be enumerated exhaustively.

### 2. Minimum-distance decoding is well-defined for any finite code

Let $y \in \mathbb{F}_2^n$ be the received vector. Define

$$\hat{c} = \arg\min_{c \in \mathcal{R}(r,m)} d_H(y, c),$$

where $d_H$ is the Hamming distance. Because $\mathcal{R}(r,m)$ is a **finite**
set, the minimum of $d_H(y,\cdot)$ over the code is attained (a minimum of a fun
ction over a finite set always exists). Therefore the decoder

$$D(y) = \hat{c}$$

is a **total, well-defined function** on $\mathbb{F}_2^n$. No obstruction — alge
braic, combinatorial, or information-theoretic — prevents its definition. This i
s the standard *minimum-distance decoder*, and it coincides with maximum-likelih
ood decoding on a binary symmetric channel.

### 3. Correctness: it corrects up to $\lfloor (d-1)/2 \rfloor$ errors

The minimum distance of $\mathcal{R}(r,m)$ is $d = 2^{m-r}$. A standard result o
f coding theory states that minimum-distance decoding corrects all error pattern
s of weight $\le \lfloor (d-1)/2 \rfloor = 2^{m-r-1}-1$:

- If $y = c + e$ with $\mathrm{wt}(e) \le \lfloor(d-1)/2\rfloor$, then for any o
ther codeword $c' \ne c$,
  $$d_H(y,c') = \mathrm{wt}(c - c' + e) \ge d - \mathrm{wt}(e) \ge d - \lfloor(d
-1)/2\rfloor > \lfloor(d-1)/2\rfloor \ge \mathrm{wt}(e) = d_H(y,c),$$
  so $c$ is the unique nearest codeword and the decoder outputs $\hat c = c$.

Thus the brute-force comparison decoder is **correct** within the guaranteed err
or-correction radius, exactly as any other decoder for the code.

### 4. The only issue is complexity, not possibility

Enumerating all $2^k$ codewords and computing $n$-length Hamming distances costs
 $O(n \cdot 2^k)$ operations. For small $r,m$ this is trivial; for large paramet
ers it becomes expensive (for fixed $r\ge 2$, $k = \Theta(m^r)$ so $2^k$ is supe
r-polynomial in $n=2^m$). This is a **computational efficiency** concern, not a
question of *possibility*. Indeed Reed–Muller codes admit efficient dedicated de
coders (Reed's majority-logic decoder runs in $O(n^2)$), but the existence of fa
ster algorithms does not invalidate the brute-force one — it only makes it unnec
essary in practice.

### 5. Conclusion

Because $\mathcal{R}(r,m)$ is a finite set of codewords, the function "compare $
y$ to every codeword and return the closest" is well-defined, total, and correct
 up to the code's guaranteed error-correction radius. Therefore **yes**, decodin
g Reed–Muller codes by exhaustive comparison to all codewords is possible. The b
rute-force procedure is always valid; it is merely not the most efficient method
 for large parameters.
