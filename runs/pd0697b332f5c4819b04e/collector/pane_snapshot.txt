### Algorithm: Insertion Sort with Ternary Search

**Setup.** We have 365 cards with distinct numbers. We build a sorted list incre
mentally, starting with one card and inserting the remaining 364 cards one at a
time. At each stage, we maintain a fully sorted list of all cards inserted so fa
r.

**Key Tool: Ternary Search Step.** Suppose we have a sorted list $L[0] < L[1] <
\cdots < L[i-1]$ of size $i$, and we wish to insert a new card $x$. There are $i
+1$ possible positions for $x$ (before $L[0]$, between consecutive elements, or
after $L[i-1]$). We maintain a search interval $[a, b]$ of candidate positions,
initially $[0, i]$, so the interval has $m = b - a + 1$ candidate positions.

**When $m \geq 3$:** We select two pivot elements from the sorted list at positi
ons
$$p = a + \left\lfloor \frac{m-1}{3} \right\rfloor, \qquad q = a + \left\lfloor
\frac{2(m-1)}{3} \right\rfloor,$$
where $a \leq p < q \leq b-1$ (valid since $m \geq 3$ ensures at least 2 element
s are available in the interval). We issue one query on the three cards $\{x, L[
p], L[q]\}$. The response reveals their complete order, telling us:
- If $x < L[p]$: the new interval is $[a, p]$, of size $p - a + 1$.
- If $L[p] < x < L[q]$: the new interval is $[p+1, q]$, of size $q - p$.
- If $x > L[q]$: the new interval is $[q+1, b]$, of size $b - q$.

By our choice of $p$ and $q$, each of the three resulting intervals has size at
most $\lceil m/3 \rceil$. (Verification: for $m = 3$, the split is $1+1+1$; for
$m = 4$, it is $2+1+1$; for $m = 5$, it is $2+1+2$; for $m = 6$, it is $2+2+2$;
for $m = 7$, it is $3+2+2$; and so on — in each case the maximum part is $\lceil
 m/3 \rceil$.)

**When $m = 2$:** The interval contains exactly 2 candidate positions, meaning $
x$'s position is determined by a single comparison with one list element. We iss
ue one query on $\{x, L[a], z\}$ where $z$ is any third card distinct from $x$ a
nd $L[a]$ (such a card always exists since there are 365 cards total). The query
 reveals the order of all three, in particular the comparison between $x$ and $L
[a]$, which resolves the interval. This costs 1 query.

**When $m = 1$:** The position is already determined. Zero queries needed.

**Query Count per Insertion.** Starting with $m = i+1$ candidate positions, each
 ternary search step (for $m \geq 3$) reduces $m$ to at most $\lceil m/3 \rceil$
, and the final step (when $m = 2$) costs 1 query. The total number of queries t
o insert into a list of size $i$ is:
$$Q(i) = \lceil \log_3(i+1) \rceil.$$
This holds because after $k$ steps the interval size is at most $\lceil (i+1)/3^
k \rceil$, and we need this to reach 1, requiring $k = \lceil \log_3(i+1) \rceil
$ steps (with the last step handling $m=2$ as described).

### Total Query Count

We insert cards 2 through 365, i.e., $i$ ranges from 1 to 364. The total number
of queries is:
$$T = \sum_{i=1}^{364} \lceil \log_3(i+1) \rceil.$$

We evaluate this sum by grouping terms by the value of $\lceil \log_3(i+1) \rcei

| $k$ | Range of $i$ | Count | Queries |

| 2 | $3 \leq i \leq 8$ | 6 | $6 \times 2 = 12$ |
| 3 | $9 \leq i \leq 26$ | 18 | $18 \times 3 = 54$ |
| 4 | $27 \leq i \leq 80$ | 54 | $54 \times 4 = 216$ |
| 5 | $81 \leq i \leq 242$ | 162 | $162 \times 5 = 810$ |
| 6 | $243 \leq i \leq 364$ | 122 | $122 \times 6 = 732$ |

(These ranges use $3^0=1, 3^1=3, 3^2=9, 3^3=27, 3^4=81, 3^5=243, 3^6=729$.)

The total count of insertions is $2 + 6 + 18 + 54 + 162 + 122 = 364$. ✓

The total number of queries is:
$$T = 2 + 12 + 54 + 216 + 810 + 732 = 1826.$$

### Conclusion

$$1826 \leq 2000.$$

The algorithm determines the complete order of all 365 cards using at most 1826
queries in the worst case, which is within the budget of 2000. Therefore, **yes*
