# Problem

In a futuristic data center, a master server stores a massive central file. To ensure redundancy and security, this file must be capable of being partitioned into two different configurations without any data loss or fractional bytes:

First, the file can be split into exactly **2,002 separate data packets**, where every single packet has an identical **checksum** (defined as the sum of the digits of its size in bytes).

Second, the same file can be split into exactly **2,003 separate data packets**, where again, every single packet has an identical **checksum** (the sum of the digits of its size in bytes).

Each data packet in both configurations must have a size that is a **positive integer** number of bytes. 

What is the smallest possible size (in bytes) of this central file?
