that computes a partial function $f:\mathbb N\rightharpoonup\mathbb N$ under the

and $1$; the blank $B$ is a separate designated symbol (as is standard, e.g. in
Sipser/Hopcroft–Ullman). This is what makes binary I/O unambiguous (the blank
delimits the finite input/output string). A remark at the end addresses the
variant where the blank is required to be one of ${0,1}$.

Both $T$ and $T'$ are taken to be single-tape machines with a two-way infinite
tape; the result for other geometries follows from the standard equivalences.

Proof

1. Encoding the large alphabet in binary

Let $|\Sigma|=k$ and let $\beta\in\Sigma$ be $T$'s blank. Pick $n:=\lceil\log_2
k\rceil$, so $2^n\ge k$. Choose an injective code $$ c:
\Sigma\longrightarrow{0,1}^n \qquad\text{with}\qquad c(\beta)=0^n . $$
(Injectivity is possible because $2^n\ge k$; we simply reserve the all-zero word
for the blank.) Extend $c$ to tape contents block-wise: a tape string $
\sigma_1\sigma_2\sigma_3\ldots$ is represented on $T'$'s tape as the
concatenation $c(\sigma_1),c(\sigma_2),c(\sigma_3)\ldots$, i.e. as a sequence of
$n$-bit blocks.

2. The simulation (core construction)

$T'$ simulates $T$ step by step. The invariant maintained throughout the
simulation is:

│ (Inv) $T'$'s head always rests on the first bit of some block (a block
│ boundary), and that block is exactly the block encoding the symbol under $T$'s
│ head.

Because $T'$ starts (after preprocessing) with its head at a block boundary and
every movement it makes is by a multiple of $n$ cells, the invariant "head at a
block boundary" is preserved purely by the finite control — $T'$ never needs to
know any absolute tape coordinate.

$T'$'s finite control stores:

  • the current state $q$ of $T$;
  • a "phase" component ($\textsf{read}/\textsf{write}/\textsf{move}$);
  • an $n$-bit accumulator (used while reading or writing a block); since $n$ is
  a fixed constant of the construction, this is a finite amount of information,
  hence realizable by finitely many states.

To simulate one transition $\delta(q,\sigma)=(q',\sigma',D)$ of $T$:

  1. Read. From the current block boundary, $T'$ moves right $n$ times, reading
  one bit per cell. A cell containing the blank $B$ is read as $0$ (this is how
  the infinite blank region of $T$'s tape, encoded as $0^n=c(\beta)$ blocks, is
  recovered). The $n$ collected bits form a word $w\in{0,1}^n$; by injectivity
  of $c$ there is a unique $\sigma$ with $c(\sigma)=w$. $T'$ stores $\sigma$
  (equivalently, $w$) in its control, then moves left $n$ times to return to the
  block boundary.
  2. Write. $T'$ looks up $\delta(q,\sigma)=(q',\sigma',D)$ (hard-wired into its
  transition table). It writes the $n$ bits of $c(\sigma')$ into the current
  block — write bit, move right, write bit, …, for $n$ steps — then moves left
  $n$ times back to the boundary. (Writing only ever puts $0$ or $1$ on the
  tape, never $B$, since $c$ takes values in ${0,1}^n$.)
  3. Move. If $D=R$, $T'$ moves right $n$ cells — landing on the first bit of
  the next block. If $D=L$, it moves left $n$ cells — landing on the first bit
  of the previous block. It updates its stored state to $q'$.

Each simulated step of $T$ costs $O(n)$ steps of $T'$, a fixed constant factor.
The finite control is finite because $n$, $|\Sigma|$, and $|Q|$ are all fixed.
Crucially, the blank region is handled correctly: a block sitting in the never-
written part of $T'$'s tape consists of $B$'s, which are read as $0$'s, yielding
$0^n=c(\beta)$ — exactly $T$'s blank. Conversely, when $T$ writes $\beta$
somewhere, $T'$ writes $0^n$ there, which on later reading is again interpreted
as $\beta$.

Thus, after the simulation reaches $T$'s halting state, $T'$'s tape is precisely
the block-encoding of $T$'s tape content, with $T'$'s head at the block encoding
$T$'s head position.

3. Preprocessing — expanding the input

$T'$'s input is the binary representation $w=b_1b_2\ldots b_m\in{0,1}^*$ of
$n\in\mathbb N$, written on the tape followed by blanks $B$, with the head at
$b_1$. Before simulating, $T'$ expands it into block form $c(b_1)c(b_2)\ldots
c(b_m)$, still followed by $B$'s, with the head at the first bit of $c(b_1)$ (a
block boundary, establishing invariant (Inv)).

This is a standard, computable tape transformation implementable by a ${0,1}$-TM
using $B$ as an end-marker. Concretely, $T'$ processes the input left to right.
At each step it is positioned on the next unexpanded bit $b_i$; it reads $b_i$,
then inserts $n-1$ blank cells immediately to its right (shifting the still-
unexpanded suffix $b_{i+1}\ldots b_m$ rightward by $n-1$), and fills those new
cells with the remaining $n-1$ bits of $c(b_i)$. The single-cell insert-and-
shift is the usual carry routine — feasible because $B$ is distinguishable from
$0,1$, so $T'$ can locate the right end of the non-blank region and carry
symbols rightward one position at a time. Repeating this for $i=1,\ldots,m$
yields the fully expanded tape. The procedure halts when $T'$ reaches the blank
$B$ marking the end of the input.

4. Postprocessing — compressing the output

When (and only when) $T$ halts, $T'$'s tape holds the block-encoding of $T$'s
final tape. Since $T$'s output is a binary string (the binary representation of
$f(n)$), the relevant output region consists solely of blocks $c(0)$ and $c(1)$
(surrounded by $c(\beta)=0^n$ blank-blocks and, beyond them, $B$'s). $T'$
compresses this region back to single bits: it scans block by block from the
appropriate starting position (the block encoding $T$'s head position, exactly
where (Inv) says $T'$'s head already is), and for each block writes the single
bit $0$ if the block is $c(0)$, the single bit $1$ if it is $c(1)$, shifting the
accumulated output left so that the final tape is an ordinary binary string
followed by $B$'s. This is the exact inverse of the preprocessing expansion and
is implementable by the same carry-shift technique. The output convention
applied is the same one $T$ uses (e.g. "the binary string on the tape starting
at the head up to the first blank"), because the simulation reproduces $T$'s
tape and head position faithfully up to the encoding $c$.

5. Correctness

Let $g$ be the partial function computed by $T'$.

  • Agreement on the domain. Suppose $T$ halts on input $n$ with output $f(n)$.
  By construction, preprocessing turns the binary input into its block-encoding;
  the simulation reproduces $T$'s entire computation faithfully (each $T$-
  transition is mirrored, the blank is encoded/decoded consistently via
  $c(\beta)=0^n$, and the head-position invariant (Inv) is maintained);
  postprocessing decodes $T$'s final binary output tape back to a plain binary
  string. Hence $T'$ halts on input $n$ and outputs $f(n)$, so $f(n)=g(n)$.
  • Agreement on divergence. If $T$ does not halt on $n$, the simulation never
  reaches $T$'s halting state, so $T'$ never proceeds to postprocessing and does
  not halt either. Hence $g$ is undefined exactly where $f$ is.

Therefore $g=f$ as partial functions $\mathbb N\rightharpoonup\mathbb N$.

6. Remark on the blank-in-${0,1}$ variant

If one insists that the blank itself must be one of ${0,1}$ (say blank $=0$),
the only obstacle is the trailing-zero ambiguity: a binary input such as $1010$
cannot be distinguished from $1010,0,0,0\ldots$ by scanning for the blank. This
is resolved by any standard self-delimiting I/O convention that does not alter
the computed partial function — for instance, prefixing the binary
representation by its length in unary (a block of $1$'s followed by a $0$), or
using a doubled-bit encoding $0\mapsto 00,;1\mapsto 11$ with the separator
pattern $01$ marking the end. Under such a convention the preprocessing/
postprocessing routines locate string ends by the delimiter rather than by the
blank, and the simulation itself is unchanged (it never needs to find a tape
"end" — it only ever reads the block under the head and steps to an adjacent
block). The partial function $\mathbb N\rightharpoonup\mathbb N$ computed is the
same; only the concrete tape layout of the I/O is recoded. Hence the theorem
holds in this variant as well.

────────────────────────────────────────────────────────────────────────────────

Conclusion

A Turing machine over any finite alphabet $\Sigma\supseteq{0,1}$ computing a
partial function $\mathbb N\rightharpoonup\mathbb N$ in binary can be simulated,
preserving exactly the computed partial function, by a Turing machine whose non-
blank alphabet is ${0,1}$. The construction is: fix a binary block-encoding $c:
\Sigma\to{0,1}^n$ with $c(\text{blank})=0^n$; expand the input into blocks;
simulate each transition of $T$ by reading, rewriting, and block-jumping on
$T'$'s tape (a constant-factor $O(n)$ overhead, all in the finite control); and
compress the output back to binary. Therefore the two models are equivalent: the
binary alphabet ${0,1}$ is computationally universal among finite alphabets.
