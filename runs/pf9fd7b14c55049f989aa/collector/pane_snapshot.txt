## Problem Interpretation

We are given an unweighted graph \(G=(V,E)\) with \(|V|=n\) and two distinguishe
d vertices \(u,v\). The natural reading that makes both \(u\) and \(v\) meaningf
ul is:

> **Does there exist a Hamiltonian cycle of \(G\) that traverses the edge \((u,v
)\)? If yes, what is the length of the shortest such cycle?**

(If \((u,v)\notin E\) the answer is immediately "no", since a cycle cannot use a
 non-edge. A Hamiltonian cycle is rotationally symmetric, so designating a "star
ting vertex" alone would make one of \(u,v\) redundant; requiring the cycle to p
ass through the specific edge \((u,v)\) is the interpretation under which both v
ertices play a role.)

---

## Main Theorem

**(a)** The decision problem "does \(G\) contain a Hamiltonian cycle through edg
e \((u,v)\)?" is **NP-complete**.

**(b)** If such a cycle exists, **every** such cycle has length exactly \(n=|V|\
); hence the shortest one has length \(n\).

---

## Proof of (b) — the length is always \(n\)

A Hamiltonian cycle is, by definition, a closed walk
\[
x_0\to x_1\to\cdots\to x_{n-1}\to x_0
\]
in which every vertex of \(V\) appears exactly once among \(x_0,\dots,x_{n-1}\)
and every consecutive pair (including the wrap-around pair \((x_{n-1},x_0)\)) is
 an edge of \(G\). Such a cycle uses exactly \(n\) edges, one for each vertex. S
ince the graph is unweighted, the length of the cycle equals its edge count, nam
ely \(n\).

Therefore **all** Hamiltonian cycles of \(G\) have the same length \(n\); the "s
hortest" one is simply \(n\). The edge constraint \((u,v)\) only affects *existe
nce*, not length. ∎

---

## Proof of (a) — NP-completeness

**Membership in NP.** A certificate is an ordering \((x_0,\dots,x_{n-1})\) of al
l vertices with, say, \(x_0=u,\;x_1=v\) (forcing the edge \((u,v)\) to be used).
 Verification requires checking: (i) all \(n\) vertices appear exactly once, (ii
) each consecutive pair and the pair \((x_{n-1},x_0)\) is an edge, (iii) the edg
e \((u,v)\) is among the used edges. All checks run in \(O(n+|E|)\) time. Hence
the problem is in NP.

**NP-hardness.** We reduce from the **Hamiltonian Path with specified endpoints*
* problem, which is well known to be NP-complete:

> *Input:* a graph \(H=(V_H,E_H)\) and two vertices \(s,t\in V_H\).
> *Question:* does \(H\) contain a Hamiltonian path from \(s\) to \(t\)?

(That this is NP-complete follows from the standard reduction from ordinary Hami
ltonian Cycle: given a graph \(G'\) and a vertex \(w\), split \(w\) into two ver
tices \(s,t\) inheriting \(w\)'s neighbors, then a Hamiltonian cycle of \(G'\) c
orresponds bijectively to a Hamiltonian path from \(s\) to \(t\) in the modified
 graph.)

**Reduction.** Given an instance \((H,s,t)\) of Hamiltonian-Path-with-endpoints,
 construct \(G\) from \(H\) by adding the edge \((s,t)\) if it is not already pr
esent, and set \(u:=s,\;v:=t\). This construction is polynomial (a single edge i
nsertion).

**Correctness.**
* (\(\Rightarrow\)) If \(H\) has a Hamiltonian path \(s=x_0,x_1,\dots,x_{n-1}=t\
), then appending the edge \((t,s)=(v,u)\) — which is present in \(G\) by constr
uction — yields the cycle
\[
s=x_0\to x_1\to\cdots\to x_{n-1}=t\to s,
\]
which visits every vertex exactly once, returns to the start, and traverses the
edge \((u,v)=(s,t)\). So \(G\) has a Hamiltonian cycle through \((u,v)\).
* (\(\Leftarrow\)) Conversely, suppose \(G\) has a Hamiltonian cycle through edg
e \((u,v)=(s,t)\). Deleting the edge \((s,t)\) from that cycle leaves a Hamilton
ian path from \(s\) to \(t\) using only edges of \(G\). Every edge of this path
other than the deleted \((s,t)\) is an edge of \(H\) (we only *added* \((s,t)\),
 nothing else), so it is in fact a Hamiltonian path from \(s\) to \(t\) in \(H\)
.

Thus \(H\) has a Hamiltonian path from \(s\) to \(t\) **iff** \(G\) has a Hamilt
onian cycle through \((u,v)\). The reduction is polynomial, so the problem is NP
-hard.

Combining membership in NP and NP-hardness, the decision problem is **NP-complet
e**. ∎

---

## Conclusion

- **Decision:** Determining whether a Hamiltonian cycle through edge \((u,v)\) e
xists is **NP-complete**; no polynomial-time algorithm is known, and finding one
 would imply \(P=NP\). If \((u,v)\notin E\) the answer is trivially **no**.
- **Optimization:** Whenever such a cycle exists, its length is exactly \(n=|V|\
) (the number of vertices), independent of which edge is forced or which cycle i
s chosen. Hence the length of the shortest such cycle is
\[
\boxed{\,n=|V|\,}.
\]
