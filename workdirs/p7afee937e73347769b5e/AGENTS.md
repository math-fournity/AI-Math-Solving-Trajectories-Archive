# Problem

In a specialized digital security lab, an engineer is testing a two-stage encryption algorithm. The algorithm begins with an initial security code—a positive integer consisting of at most six digits. 

To generate the next code in the sequence, the system must be able to perform one of two specific operations: it can either calculate the sum of the digits of the current code or the product of the digits of the current code. The engineer discovers a "Persistent Oddity" vulnerability: for certain starting codes, every single integer generated by these recursive operations (regardless of which of the two operations is chosen at any step, and for any number of steps) is an odd number.

How many such starting security codes (integers from 1 to 999,999) exist where every possible subsequent value generated by either the sum or the product of the digits remains odd indefinitely?
